配置说明

手机上只装一次快捷指令，之后每台设备只贴一条推送链接。本页和下面的下载是配置入口，不含设备密钥，也不能用来上报短信。导入和通知要在你的 iPhone 上确认，这个页面不会替手机执行。

版本与配置状态

  • 推荐：打开 iCloud 分享链接安装 SMSinBox Next（已签名）。导入后只填写推送链接。
  • 备用：设备页可下载未签名的 SMSinBox-iOS.shortcut；iOS 15 及更高版本可能拒绝导入。
  • iCloud：https://www.icloud.com/shortcuts/cdfde24d823a43318ee651bb4d2c9494 。不要使用来路不明的其它分享链接。
  • 配置状态：本页看不到手机上的自动化开关。自动化里 content 必须用「信息 › 内容」，不要用「快捷指令输入」。收到 device 为 iOS 的短信后，设备卡片会写成「已收到 iOS 短信」。发送测试消息不会写成 iOS。

推送链接在新建设备或轮换时出现一次，形如 https://<你的域名>/api/v1/ingest/psh_...。请立刻复制。刷新后无法再查看，丢掉就点该设备的「轮换」。不要把链接发到聊天或工单。Workers 的平台访问日志仍可能看到路径。

SMSinBox Next / SMSinBox-iOS

接近全部短信。适合普通号码。优先用 iCloud 分享链接；备用下载导入时只填推送链接。自动化条件用「信息包含一个空格」。content 用「信息 › 内容」。

已知限制

推荐用上方 iCloud 已签名分享链接。仓库下载的备用文件未签名；Linux 上无法运行 shortcuts sign，iOS 15 及更高版本经常拒绝未签名文件。被拒绝时按手动步骤新建。不要使用来路不明的其它链接。自动化里 content 必须用「信息 › 内容」。需要关闭「运行前询问」。手机需开机联网，重启后要解锁一次。只转发文本，不支持彩信。

导入时只填推送链接。正文为空会通知「未发送：正文为空」并且不发送。读不到发件人时仍会发送，收件箱里的发件人是「（发件人为空）」；把 JSON 的 from 改成这条自动化的「发件人」才能得到号码。返回里有「请求过于频繁」时通知 429，有「推送链接无效」或「推送链接已撤销」时通知 401。没有 JSON，或系统停在「获取 URL 内容」报错，是网络失败或推送链接为空。

iOS 27 及以上
  1. 在上面新建设备，复制一次性推送链接。
  2. 优先打开上方 iCloud 分享链接安装 SMSinBox Next；或下载备用未签名文件。系统拒绝未签名文件时，用下面的手动步骤。
  3. 导入时只填写推送链接。不要把链接发给别人。
  4. 打开「快捷指令」→「自动化」，展开这条快捷指令的触发器。
  5. 打开自动化开关，关闭「运行前确认」。有「锁定时允许运行」就打开它。这就是立即运行。
  6. 全部短信选「信息包含一个空格」。只要验证码时，把条件改成包含「验证码」，并再加一条包含 code。系统不允许空条件，空格也不是真正的全量。
  7. 保存。用另一台手机发一条含「验证码 123456」的短信。重启后要先解锁一次。设备旁边的「发送测试消息」只写服务器收件箱，不会让运营商给你的手机发短信。
iOS 26 及以下
  1. 复制刚生成的推送链接。
  2. 打开「快捷指令」→「自动化」→ 点「+」→「信息」。
  3. 发件人可以选任何人。短码常常不在通讯录里，要靠正文条件。条件选「信息包含一个空格」，或「包含」验证码 / code。空格匹配不到没有空格的短码。
  4. 选择「立即运行」，关闭「运行前询问」。
  5. 把下载的快捷指令加进这个自动化。系统拒绝未签名文件时，改用手动步骤。
  6. 保存。手机重启后要先解锁一次，自动化才会继续跑。
手动添加「获取 URL 内容」
  1. 按上面对应系统版本新建「信息」自动化，选立即运行，并关掉运行前询问或运行前确认。
  2. 「信息 › 内容」没有内容时，通知「未发送：正文为空」，然后停止。
  3. 「信息 › 发件人」没有内容时，用文本「（发件人为空）」；否则用「信息 › 发件人」。把结果设成变量「发件人」。
  4. 添加「文本」，内容填推送链接。
  5. 添加「获取 URL 内容」。URL 选上一步的文本，方法 POST，打开显示标头。
  6. 标头只加 Content-Type，值是 application/json。不要加 Authorization。
  7. 请求体选 JSON：from 用变量「发件人」；content 用「信息 › 内容」（不要用「快捷指令输入」）；timestamp 用当前日期；device 填 iOS。
  8. 看返回的文字。包含「请求过于频繁」就通知 429。包含「推送链接」就通知 401，然后到设备页轮换。包含 false 就通知服务器拒绝了这条短信。不包含 ok 就通知网络失败。否则通知「已转发」。
已有快捷指令

已经装在手机里的旧快捷指令不用改。它们继续 POST 到 /api/v1/sms，请求头仍是 Authorization: Bearer <token>。Android 也继续用这个地址和 Bearer，见 Android 一节。

  1. 「文本」：Webhook URL，形如 https://<你的域名>/api/v1/sms。
  2. 「文本」：设备 token。
  3. 「文本」：Bearer （Bearer 后面有一个空格），再插入 token 文本的输出。
  4. 「获取 URL 内容」：URL 选第一个文本，方法 POST。标头 Authorization 选 Bearer 文本，Content-Type 填 application/json。
  5. 请求体 JSON 的字段仍是 from、content、timestamp、device。

收藏夹里的 ?variant=code 仍会下载旧的关键词模板，那不是新的主路径。新的安装只用上面这一份。要不要只收验证码，由手机上的自动化条件决定。

共享来的自动化默认是关闭的。完整步骤和常见问题写在仓库的 docs/ios-setup.md。
