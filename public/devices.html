设备管理

每个设备有自己的 Bearer token，以及一条推送链接。Bearer 只在创建时显示一次。推送链接在创建或轮换时显示一次。推送链接可以轮换或撤销，短信会保留。Bearer 丢失后，仍然要删除设备并新建。

Bearer token，只显示这一次

请立刻保存。关闭或刷新页面后无法再查看。请求头使用 Authorization: Bearer <token>。Android 和已经装好的旧快捷指令继续用它。

推送链接，只显示这一次

贴进已经装好的那一条快捷指令。它等同设备密钥，不要发到聊天或工单。刷新后无法再查看，丢掉请轮换。

iOS 配置

手机上只装一次快捷指令，之后每台设备只贴一条推送链接。本页和下面的下载是配置入口，不含设备密钥，也不能用来上报短信。

推送链接在新建设备或轮换时出现一次，形如 https://<你的域名>/api/v1/ingest/psh_...。请立刻复制。刷新后无法再查看，丢掉就点该设备的「轮换」。不要把链接发到聊天或工单。Workers 的平台访问日志仍可能看到路径。

导入时只填推送链接。自动化条件在手机上设置：全部短信用「信息包含一个空格」，只要验证码时用「验证码」或 code。推送链接不校验 HMAC。同一台设备如果填了签名密钥，Android 的 Bearer 仍然要签名。

iOS 27 及以上
  1. 在上面新建设备，复制一次性推送链接。
  2. 下载快捷指令后在 iPhone 上打开。若系统拒绝未签名文件，按下面的手动步骤新建，或等文档里的 iCloud 链接（尚未发布就先用手动步骤）。
  3. 导入时只填写推送链接。不要把链接发给别人。
  4. 打开「快捷指令」→「自动化」，展开这条快捷指令的触发器。
  5. 打开自动化开关，关闭「运行前确认」，有「锁定时允许运行」就打开它。
  6. 全部短信选「信息包含一个空格」。只要验证码时，把条件改成包含「验证码」，并再加一条包含 code。
  7. 保存。用另一台手机发一条含「验证码 123456」的短信，或点设备旁边的「发送测试消息」。
iOS 26 及以下
  1. 复制刚生成的推送链接。
  2. 打开「快捷指令」→「自动化」→ 点「+」→「信息」。
  3. 发件人可以选任何人。条件选「信息包含一个空格」，或「包含」验证码 / code。
  4. 选择「立即运行」，关闭「运行前询问」。
  5. 把下载的快捷指令加进这个自动化。系统拒绝未签名文件时，改用手动步骤。
  6. 保存。手机重启后要先解锁一次，自动化才会继续跑。
手动添加「获取 URL 内容」
  1. 按上面对应系统版本新建「信息」自动化，并设好触发条件。
  2. 添加「文本」，内容填推送链接。
  3. 添加「获取 URL 内容」。URL 选上一步的文本，方法 POST，打开显示标头。
  4. 标头只加 Content-Type，值是 application/json。不要加 Authorization。
  5. 请求体选 JSON：from 用快捷指令输入的发件人（Sender），空的话改成自动化的「发件人」；content 用快捷指令输入；timestamp 用当前日期；device 填 iOS。
  6. 可选「显示通知」，标题 SMSinBox，正文「已转发」。关闭运行前询问后保存。
已有快捷指令和 Android

已经装在手机里的旧快捷指令不用改。它们继续 POST 到 /api/v1/sms，请求头仍是 Authorization: Bearer <token>。Android 也继续用这个地址和 Bearer，见下一节。

  1. 「文本」：Webhook URL，形如 https://<你的域名>/api/v1/sms。
  2. 「文本」：设备 token。
  3. 「文本」：Bearer （Bearer 后面有一个空格），再插入 token 文本的输出。
  4. 「获取 URL 内容」：URL 选第一个文本，方法 POST。标头 Authorization 选 Bearer 文本，Content-Type 填 application/json。
  5. 请求体 JSON 的字段仍是 from、content、timestamp、device。

收藏夹里的 ?variant=code 仍会下载旧的关键词模板。新的安装只用上面的统一模板。要不要只收验证码，由手机上的自动化条件决定。

共享来的自动化默认是关闭的。手机需要开机并联网，只转发文本，不支持彩信。分版本步骤、常见问题和限制写在仓库的 docs/ios-setup.md。

              可选 HMAC
              
创建设备时如果填写了签名密钥，之后每次用 Bearer 上报都必须带 X-Timestamp（Unix 秒或毫秒）和 X-Signature。签名是 HMAC-SHA256(X-Timestamp + 原始请求体, secret) 的十六进制，时间窗口 ±5 分钟。SmsForwarder 的默认配置不会签名，给它用时密钥请留空。

              
推送链接不要求 HMAC。快捷指令签不了名，所以这条链接故意不校验签名。同一台设备可以同时把 Bearer 留给 Android，把推送链接留给 iOS。装了推送链接，就等于为这台设备多开了一扇不校验 HMAC 的门。
