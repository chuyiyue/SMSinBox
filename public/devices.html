设备管理

每台设备卡片显示名称、平台、状态、设备 ID 和最近一次短信。Bearer token 只在创建时出现一次。推送链接在创建或轮换后的黄框里出现一次，可以一键复制。数据库只存哈希，刷新后不能再查看明文，丢掉请轮换。生成、轮换和撤销都会先确认。Bearer 丢失后，仍然要删除设备并新建。

Bearer token，只显示这一次

请立刻保存。关闭或刷新页面后无法再查看。请求头使用 Authorization: Bearer <token>。Android 和已经装好的旧快捷指令继续用它。丢失后要删除设备并新建。

推送链接，只显示这一次

贴进已经装好的那一条快捷指令。它等同设备密钥，不要发到聊天或工单。数据库只保存哈希，刷新后不能再显示明文。丢掉请在这台设备上点「轮换」。

iOS 配置

手机上只装一次快捷指令，之后每台设备只贴一条推送链接。本页和下面的下载是配置入口，不含设备密钥，也不能用来上报短信。导入和通知要在你的 iPhone 上确认，这个页面不会替手机执行。

版本与配置状态

  • 模板：统一快捷指令 SMSinBox-iOS.shortcut。导入时只填写推送链接。
  • 签名：未签名。iOS 15 及更高版本可能拒绝导入。
  • iCloud：尚未发布。不要使用来路不明的分享链接。
  • 配置状态：本页看不到手机上的自动化开关。收到 device 为 iOS 的短信后，设备卡片会写成「已收到 iOS 短信」。发送测试消息不会写成 iOS。

推送链接在新建设备或轮换时出现一次，形如 https://<你的域名>/api/v1/ingest/psh_...。请立刻复制。刷新后无法再查看，丢掉就点该设备的「轮换」。不要把链接发到聊天或工单。Workers 的平台访问日志仍可能看到路径。

下载快捷指令

文件未签名。Linux 上无法运行 shortcuts sign，iOS 15 及更高版本经常拒绝未签名文件。被拒绝时按手动步骤新建。iCloud 分享链接尚未发布，不要使用来路不明的链接。

导入时只填推送链接。正文为空会通知「未发送：正文为空」并且不发送。读不到发件人时仍会发送，收件箱里的发件人是「（发件人为空）」；把 JSON 的 from 改成这条自动化的「发件人」才能得到号码。返回里有「请求过于频繁」时通知 429，有「推送链接无效」或「推送链接已撤销」时通知 401。没有 JSON，或系统停在「获取 URL 内容」报错，是网络失败或推送链接为空。

只要验证码时不要再下载第二份快捷指令。用下面同一条自动化，把条件改成包含「验证码」，并再加一条包含 code。接近全部短信用「信息包含一个空格」，没有空格的短码匹配不到。推送链接不校验 HMAC。同一台设备如果填了签名密钥，Android 的 Bearer 仍然要签名。

iOS 27 及以上
  1. 在上面新建设备，复制一次性推送链接。
  2. 下载快捷指令后在 iPhone 上打开。系统拒绝未签名文件时，用下面的手动步骤。iCloud 链接尚未发布。
  3. 导入时只填写推送链接。不要把链接发给别人。
  4. 打开「快捷指令」→「自动化」，展开这条快捷指令的触发器。
  5. 打开自动化开关，关闭「运行前确认」。有「锁定时允许运行」就打开它。这就是立即运行。
  6. 全部短信选「信息包含一个空格」。只要验证码时，把条件改成包含「验证码」，并再加一条包含 code。系统不允许空条件，空格也不是真正的全量。
  7. 保存。用另一台手机发一条含「验证码 123456」的短信。重启后要先解锁一次。设备旁边的「发送测试消息」只写服务器收件箱，不会让运营商给你的手机发短信。
iOS 26 及以下
  1. 复制刚生成的推送链接。
  2. 打开「快捷指令」→「自动化」→ 点「+」→「信息」。
  3. 发件人可以选任何人。短码常常不在通讯录里，要靠正文条件。条件选「信息包含一个空格」，或「包含」验证码 / code。空格匹配不到没有空格的短码。
  4. 选择「立即运行」，关闭「运行前询问」。
  5. 把下载的快捷指令加进这个自动化。系统拒绝未签名文件时，改用手动步骤。
  6. 保存。手机重启后要先解锁一次，自动化才会继续跑。
手动添加「获取 URL 内容」
  1. 按上面对应系统版本新建「信息」自动化，选立即运行，并关掉运行前询问或运行前确认。
  2. 快捷指令输入没有内容时，通知「未发送：正文为空」，然后停止。
  3. Sender 没有内容时，用文本「（发件人为空）」；否则用 Sender。把结果设成变量「发件人」。
  4. 添加「文本」，内容填推送链接。
  5. 添加「获取 URL 内容」。URL 选上一步的文本，方法 POST，打开显示标头。
  6. 标头只加 Content-Type，值是 application/json。不要加 Authorization。
  7. 请求体选 JSON：from 用变量「发件人」；content 用快捷指令输入；timestamp 用当前日期；device 填 iOS。
  8. 看返回的文字。包含「请求过于频繁」就通知 429。包含「推送链接」就通知 401，然后到设备页轮换。包含 false 就通知服务器拒绝了这条短信。不包含 ok 就通知网络失败。否则通知「已转发」。
已有快捷指令和 Android

已经装在手机里的旧快捷指令不用改。它们继续 POST 到 /api/v1/sms，请求头仍是 Authorization: Bearer <token>。Android 也继续用这个地址和 Bearer，见下一节。

  1. 「文本」：Webhook URL，形如 https://<你的域名>/api/v1/sms。
  2. 「文本」：设备 token。
  3. 「文本」：Bearer （Bearer 后面有一个空格），再插入 token 文本的输出。
  4. 「获取 URL 内容」：URL 选第一个文本，方法 POST。标头 Authorization 选 Bearer 文本，Content-Type 填 application/json。
  5. 请求体 JSON 的字段仍是 from、content、timestamp、device。

收藏夹里的 ?variant=code 仍会下载旧的关键词模板，那不是新的主路径。新的安装只用上面这一份。要不要只收验证码，由手机上的自动化条件决定。

共享来的自动化默认是关闭的。手机需要开机并联网，重启后要解锁一次。只转发文本，不支持彩信。iCloud 尚未发布。完整步骤和常见问题写在仓库的 docs/ios-setup.md。

  2. 添加发送通道，类型选 Webhook，方法 POST。

  4. 请求头添加 Authorization: Bearer 设备token 和 Content-Type: application/json。
  5. 请求体使用下面的模板，然后建一条「收到短信时转发到该通道」的规则。

              
            

            

              可选 HMAC
              
创建设备时如果填写了签名密钥，之后每次用 Bearer 上报都必须带 X-Timestamp（Unix 秒或毫秒）和 X-Signature。签名是 HMAC-SHA256(X-Timestamp + 原始请求体, secret) 的十六进制，时间窗口 ±5 分钟。SmsForwarder 的默认配置不会签名，给它用时密钥请留空。

              
推送链接不要求 HMAC。快捷指令签不了名，所以这条链接故意不校验签名。同一台设备可以同时把 Bearer 留给 Android，把推送链接留给 iOS。装了推送链接，就等于为这台设备多开了一扇不校验 HMAC 的门。
