# iOS 接入

iPhone 没有安卓那种常驻短信转发器。SMSinBox 用「快捷指令」的个人信息自动化：短信到达后，向创建设备时给出的那一条推送链接发送 JSON。链接形如 `https://<你的域名>/api/v1/ingest/psh_...`。正文是 `{ "from", "content", "timestamp", "device": "iOS" }`，标头只有 `Content-Type: application/json`。不要加 `Authorization`。

设备页在新建设备时同时给出一次性 Bearer token 和一次性推送链接。iOS 只需要复制推送链接。页面也可以下载统一模板，并给已有设备发送一条测试短信。测试短信正文里带有验证码 `654321`，写入收件箱，也会走已启用的推送。

配置页、下载接口和本文都不是推送地址。它们不含设备密钥，也不能用来上报短信。

## 先知道这几件事

- 仓库里的 `.shortcut` 是**未签名** XML。`shortcuts sign` 只能在 macOS 上运行，Linux 构建机签不了。iOS 15 及更高版本经常拒绝导入未签名文件。
- 可靠的做法是在 iPhone 上按本文手动新建，或使用下面的 iCloud 分享链接。链接尚未发布时，请用手动步骤。不要使用来路不明的快捷指令。
- 共享快捷指令里的自动化**默认关闭**。导入后必须自己打开开关，并关闭「运行前询问」。
- 触发器必须有匹配规则。系统不允许「全部短信」这种空条件。「信息包含一个空格」最接近全量，因为多数短信正文里有空格。没有空格的短码，把条件改成「验证码」或 `code`。这个过滤在手机上完成。服务端没有「只收验证码」开关。
- 手机要开机并联网。重启后要先解锁一次，自动化才会继续跑。
- 只转发文本短信。彩信（MMS）不会出现在收件箱里。
- 模板里的 `from` 会尝试读取快捷指令输入的 Sender。如果收到的短信发件人是空的，编辑快捷指令，把 `from` 改成自动化提供的「发件人」变量。
- 下载的统一模板**不会**写入推送链接或设备 token。导入时只问一格「推送链接」，默认是空的。同一份文件可以在多台手机上安装，每台设备贴自己的链接。
- 推送链接等同设备密钥。不要发到聊天或工单。Workers 的平台访问日志仍可能看到请求路径，应用日志会把这段路径打成 `/api/v1/ingest/:secret`。
- 推送链接不校验 HMAC。快捷指令签不了名。同一台设备如果填了签名密钥，Android 的 Bearer 仍然要签名。装了推送链接，就等于为这台设备多开了一扇不校验 HMAC 的门。
- 一台设备同时只有一条有效推送链接，长期有效，直到轮换或撤销。轮换会立刻作废手机上的旧链接，短信保留。撤销只停掉这条链接，不删设备和短信。

## 准备推送链接

1. 登录 SMSinBox，打开设备页。
2. 新建设备。名称随意。签名密钥可以留空。推送链接不会计算 HMAC。如果这台设备还要给 Android 用，并且你希望 Bearer 必须签名，可以填写密钥；iOS 这条链接仍然不签名。
3. 立刻复制推送链接。刷新页面后无法再查看。丢掉就点该设备的「轮换」，不要指望再显示一次。
4. 如果还要用 Android 或已经装好的旧快捷指令，同时复制 Bearer token。它也只在创建时出现一次。丢失后要删除设备并新建。推送链接则可以轮换。

已有设备如果还没有推送链接，点「生成推送链接」。链接已经有效时，这个按钮不会出现，请改用「轮换」，避免把手机上正在用的地址静默作废。

## iOS 27 及以上

1. 在设备页下载快捷指令（文件名 `SMSinBox-iOS.shortcut`）。
2. 在 iPhone 上打开这个文件，或打开上面的 iCloud 链接。尚未发布则不要跳过下面的手动步骤。
3. 导入时只填写推送链接。
4. 打开「快捷指令」→「自动化」，找到刚加上的项目，展开触发器。
5. 打开自动化开关。关闭「运行前确认」。如果有「锁定时允许运行」，打开它。
6. 全部短信把条件设为「信息包含一个空格」。只要验证码时，把条件改成包含「验证码」，并再加一条包含 `code`。
7. 保存。用另一台手机发一条含「验证码 123456」的短信，或在设备页点「发送测试消息」。收件箱里应出现验证码，并能复制。

## iOS 26 及以下

1. 复制刚生成的推送链接。
2. 打开「快捷指令」→「自动化」→ 点右上角「+」→ 选择「信息」。
3. 发件人可以选「任何人」，也可以只填会发验证码的号码。
4. 条件选「信息包含一个空格」。只要验证码时，改为包含「验证码」，并再加一条包含 `code`。
5. 选「立即运行」。关闭「运行前询问」。
6. 添加已导入的快捷指令。如果系统拒绝未签名文件，改用下一节，在这个自动化里手动作。
7. 保存。重启手机后先解锁一次，再发测试短信。

iOS 26 和 iOS 27 的差别主要在自动化的入口和开关名称。26 及以下从自动化标签页的「+」新建「信息」；27 及以上更常从导入的快捷指令展开触发器，再打开自动化开关。两边都要关掉运行前确认，也都必须有一条匹配规则。

## 手动添加「获取 URL 内容」

系统拒绝 `.shortcut` 文件时用这一节。先按上面对应版本建好「信息」自动化，再添加动作：

1. 「文本」：推送链接。
2. 「获取 URL 内容」：
   - URL：上一步的文本
   - 方法：POST
   - 打开「显示标头」或高级选项里的标头
   - 只加 `Content-Type`：`application/json`。不要加 `Authorization`
   - 请求体类型：JSON
   - `from`：快捷指令输入的发件人（Sender）。结果为空时，改用自动化变量「发件人」
   - `content`：快捷指令输入
   - `timestamp`：当前日期
   - `device`：文本 `iOS`
3. 可选「显示通知」，标题 `SMSinBox`，正文 `已转发`。通知失败不影响收件箱。
4. 关闭「运行前询问」，保存。

## 已有快捷指令和 Android

已经装在手机里的旧快捷指令不用改。它们继续 `POST /api/v1/sms`，请求头仍是 `Authorization: Bearer <设备 token>`。Android 的 SmsForwarder 也继续用这个地址和 Bearer，设备页「Android · SmsForwarder」一节会填出当前站点的 `/api/v1/sms`。

旧的手工动作是：

1. 「文本」：Webhook URL，形如 `https://<你的域名>/api/v1/sms`。
2. 「文本」：设备 token。
3. 「文本」：`Bearer `（Bearer 后面有一个空格），再插入上一步 token 文本的输出。
4. 「获取 URL 内容」：
   - URL：第一个文本
   - 方法：POST
   - `Authorization`：第三个文本（以 Bearer 开头的那个）
   - `Content-Type`：`application/json`
   - 请求体类型：JSON
   - `from`、`content`、`timestamp`、`device` 与上面相同
5. 只要验证码、并且快捷指令自己要停掉无关短信时，在「获取 URL 内容」之前加一个「如果」：快捷指令输入包含「验证码」，否则如果包含 `code`，否则「停止快捷指令」。

设备页只提供统一模板一个下载。收藏夹里的 `?variant=code` 仍会下载旧的关键词模板，导入时询问 Webhook URL 和设备 token。新的安装不要用它。要不要只收验证码，由手机上的自动化条件决定。

把 `psh_` 链接当作 Bearer 发到 `/api/v1/sms` 不会成功。认设备只看对应的那把钥匙。

## 常见问题

**导入文件后没有任何反应。** 共享或导入的自动化默认关闭。到「自动化」里打开开关，并关闭「运行前询问 / 运行前确认」。

**重启之后不再转发。** 解锁 iPhone 一次。自动化在重启后的第一次解锁之前不会跑。

**银行或短码短信没有进来。** 正文里往往没有空格，「包含一个空格」匹配不到。把自动化条件改成「包含 验证码」和「包含 code」。不要指望服务端再滤一遍。

**iPhone 拒绝打开 `.shortcut`。** 这是未签名文件的常见结果。请按手动步骤在手机上重建，或等维护者发布 iCloud 分享链接。不要为了导入而去掉系统的签名检查。

**收件箱里发件人是空的。** 快捷指令输入的 Sender 在部分系统版本上是空的。编辑 JSON 的 `from`，改用这个自动化提供的「发件人」变量。服务器接受空的 `from`。

**点了测试按钮，但手机没有收到短信。** 「发送测试消息」是服务器替这台设备写一条测试记录，用来确认收件箱、加密和推送。它不会让运营商发给你的手机。

**每条短信都要在手机上点确认。** 「运行前询问」还开着。关掉它，并选择立即运行。

**推送链接发到了聊天或工单。** 立刻在设备页点「轮换」。旧链接马上失效，新链接只显示一次。撤销会停掉当前链接，但不会换一把新的。

**填了签名密钥，iOS 还是能上报。** 这是预期行为。推送链接不校验 HMAC。Bearer 那条门仍然要签名。

## 限制

- 必须有匹配规则。空格是最接近「全部短信」的条件，不是真正的全量。
- 手机要开机、联网。快捷指令不在云端常驻。
- 重启后要解锁一次。
- 只有文本，没有彩信，也没有短信里的图片。
- 自动化创建之前的旧短信不会补送。
- 未签名模板可能无法导入。iCloud 链接尚未发布。
- 一条短信一分钟内、同一设备、同一发件人、正文相同，会被当成重复上报。
- 推送链接和 Bearer 各有每分钟 60 次的限额，分开计数。
