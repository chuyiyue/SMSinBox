# iOS 接入

iPhone 没有安卓那种常驻短信转发器。SMSinBox 用「快捷指令」的个人信息自动化：短信到达后，向创建设备时给出的那一条推送链接发送 JSON。链接形如 `https://<你的域名>/api/v1/ingest/<32 位十六进制密钥>`。正文是 `{ "from", "content", "timestamp", "device": "iOS" }`，标头只有 `Content-Type: application/json`。不要加 `Authorization`。

手机上只装一次统一快捷指令。每台设备只贴自己的推送链接。要不要只收验证码，改这条自动化的条件，不要再装第二套主快捷指令。

设备页在新建设备时同时给出一次性 Bearer token 和一次性推送链接。iOS 只需要复制推送链接。页面给出 iCloud 分享链接，也可下载未签名备用模板，并给已有设备发送一条测试短信。测试短信正文里带有验证码 `654321`，写入收件箱，也会走已启用的推送。它不会让运营商给你的手机发短信。

配置页、下载接口和本文都不是推送地址。它们不含设备密钥，也不能用来上报短信。

下面的导入、开关和通知，都要在你的 iPhone 上确认。本仓库在 Linux 上构建，打不开快捷指令，也不能替你跑自动化。

## 先知道这几件事

- **推荐安装**：打开下方 iCloud 分享链接（SMSinBox Next，已签名）。导入后只填写推送链接，打开自动化并关闭「运行前询问」。
- 仓库 / 设备页下载的 `.shortcut` 是**未签名** XML 备用文件。`shortcuts sign` 只能在 macOS 上运行，Linux 构建机签不了。iOS 15 及更高版本经常拒绝导入未签名文件。被拒绝时用 iCloud 链接或按本文手动新建。不要为了导入而去掉系统的签名检查。不要使用来路不明的其它快捷指令。
- 共享快捷指令里的自动化**默认关闭**。导入后必须自己打开开关，选择立即运行，并关闭「运行前询问」或「运行前确认」。
- 触发器必须有匹配规则。系统不允许「全部短信」这种空条件。「信息包含一个空格」最接近全量，因为多数短信正文里有空格。没有空格的短码、银行通知匹配不到。只要验证码时，把条件改成包含「验证码」，并再加一条包含 `code`。这个过滤在手机上完成，短信不会先上传再丢掉。服务端没有「只收验证码」开关。
- 手机要开机并联网。重启后要先解锁一次，自动化才会继续跑。
- 只转发文本短信。彩信（MMS）不会出现在收件箱里。
- 自动化里 JSON 的 `from` 必须用「信息 › 发件人」，`content` 必须用「信息 › 内容」（TriggerOutput）。不要用「快捷指令输入」——自动化直接运行时它经常是空的，服务器会返回「缺少短信内容」。
- 读不到发件人时，仍可发送并把 `from` 写成「（发件人为空）」。收件箱里看到这个占位，确认 `from` 是否绑到了「信息 › 发件人」。
- 正文没有内容时，手机会通知「未发送：正文为空」，并且不发送请求。
- 下载的统一模板**不会**写入推送链接或设备 token。导入时只问一格「推送链接」，默认是空的。同一份文件可以在多台手机上安装，每台设备贴自己的链接。
- 推送链接等同设备密钥。不要发到聊天或工单。Workers 的平台访问日志仍可能看到请求路径，应用日志会把这段路径打成 `/api/v1/ingest/:secret`。
- 推送链接不校验 HMAC。快捷指令签不了名。同一台设备如果填了签名密钥，Android 的 Bearer 仍然要签名。装了推送链接，就等于为这台设备多开了一扇不校验 HMAC 的门。
- 一台设备同时只有一条有效推送链接，长期有效，直到轮换或撤销。轮换会立刻作废手机上的旧链接，短信保留。撤销只停掉这条链接，不删设备和短信。

## iCloud 分享链接

推荐安装方式（已签名，在 Apple 设备上点链接直接导入）：

- https://www.icloud.com/shortcuts/f7880f724c5443aebffc1ab5c5b7788f

分享里的「推送链接」文本默认为空，可安全转发此链接。导入后在快捷指令里贴上你自己的推送链接（32 位十六进制密钥）。`from`＝信息 › 发件人，`content`＝信息 › 内容，`timestamp`＝当前日期，`device`＝`iOS`。不要使用来路不明的其它分享链接。

## 准备推送链接

1. 登录 SMSinBox，打开设备页。
2. 新建设备。名称随意。签名密钥可以留空。推送链接不会计算 HMAC。如果这台设备还要给 Android 用，并且你希望 Bearer 必须签名，可以填写密钥；iOS 这条链接仍然不签名。
3. 立刻复制推送链接。刷新页面后无法再查看。丢掉就点该设备的「轮换」，不要指望再显示一次。
4. 如果还要用 Android 或已经装好的旧快捷指令，同时复制 Bearer token。它也只在创建时出现一次。丢失后要删除设备并新建。推送链接则可以轮换。

已有设备如果还没有推送链接，点「生成推送链接」。链接已经有效时，这个按钮不会出现，请改用「轮换」，避免把手机上正在用的地址静默作废。生成、轮换和撤销都会先确认。

## 设备页上怎么看

设备卡片显示名称、平台、推送状态、设备 ID 和最近一次短信接收时间。平台来自最近一条短信里的 `device` 字段：快捷指令固定写成 `iOS`，测试短信写成设备名称，所以测试成功不等于 iOS 已经配好。收件箱里已经没有短信时，卡片改显示最近一次上报时间。

推送链接和 Bearer 只在创建或轮换后的黄框里出现，旁边有复制按钮，点链接本身也会选中全文。刷新页面后黄框消失。数据库只存哈希，页面没有「再显示一次」。链接丢掉就点「轮换」，旧链接马上失效。

「版本与配置状态」写的是推荐 iCloud 分享链接、备用未签名下载，以及自动化里 content 必须用「信息 › 内容」。卡片上的配置状态只能根据有没有收到短信来判断，看不到手机上的自动化开关。安装步骤仍在同一页的折叠说明里，每台设备也有「安装说明」跳到那里。窄屏上按钮会换行，链接和设备 ID 会折行。

## 手机上的通知

统一模板在发送前和收到响应后各看一次。下表是通知正文和对应处理。系统若直接停在「获取 URL 内容」的报错上、没有这些通知，那是网络失败，或推送链接是空的；快捷指令还没拿到可以判断的 JSON。

| 你看到的 | 含义 | 处理 |
|---|---|---|
| 未发送：正文为空 | 短信正文为空，或 `content` 绑错了变量 | 不发送。确认 `content` 是「信息 › 内容」，不是「快捷指令输入」 |
| 收件箱发件人是「（发件人为空）」 | Sender 是空的，短信已经发出 | 编辑「获取 URL 内容」，把 `from` 改成这条自动化的「发件人」 |
| 已转发 | 返回正文里有 `ok`，而且不是下面几种拒绝 | 到网页收件箱查看。重复上报也会显示已转发 |
| 未写入：请求过于频繁（429）。请稍后再试。 | 返回里有「请求过于频繁」 | 这条链接每分钟 60 次。等一分钟 |
| 未写入：推送链接无效或已撤销（401）。请在设备页轮换后重贴链接。 | 返回里有「推送链接」 | 链接无效或已撤销。到设备页轮换，把新链接贴回去。不要把链接发到聊天 |
| 未写入：服务器拒绝了这条短信。 | 返回里有 `false`，但不是上面两种 | 服务器拒绝了。在快捷指令里查看「获取 URL 内容」的结果 |
| 未发送：网络失败，或返回的不是 JSON。… | 返回里没有 `ok` | 检查 iPhone 是否联网，推送链接是否整段贴上 |

「已转发」只说明服务器接受了这次请求。发件人是不是空的，要看收件箱里的占位文字。

## 只要验证码

仍用上面这一份快捷指令。在「信息」自动化里：

1. 条件改成「信息包含」`验证码`。
2. 再加一条自动化，条件为包含 `code`，运行同一份快捷指令。

这样不符合条件的短信不会启动快捷指令，也不会上传。不要把收藏夹里的 `?variant=code` 当成第二条主路径。那一份是旧的关键词模板，给已经保存的下载地址用，导入时仍问 Webhook URL 和设备 token。

## iOS 27 及以上

1. 在设备页复制一次性推送链接。
2. **优先**打开上方 iCloud 分享链接安装 SMSinBox Next；若打不开，再下载备用未签名文件 `SMSinBox-iOS.shortcut`。系统拒绝未签名文件时，改用后面的手动步骤。
3. 导入时只填写推送链接。
4. 打开「快捷指令」→「自动化」，找到刚加上的项目，展开触发器。
5. 打开自动化开关。关闭「运行前确认」。如果有「锁定时允许运行」，打开它。关掉确认并允许锁定时运行，就是立即运行。
6. 全部短信把条件设为「信息包含一个空格」。只要验证码时，按上一节改条件。空格不是真正的全量。
7. 保存。用另一台手机发一条含「验证码 123456」的短信。重启手机后先解锁一次，再发。收件箱里应出现验证码，并能复制。

## iOS 26 及以下

1. 复制刚生成的推送链接。
2. 打开「快捷指令」→「自动化」→ 点右上角「+」→ 选择「信息」。
3. 发件人可以选「任何人」，也可以只填会发验证码的号码。发件人选择器往往只有通讯录，短码要靠正文条件，不要只靠选发件人。
4. 条件选「信息包含一个空格」。只要验证码时，改为包含「验证码」，并再加一条包含 `code`。
5. 选「立即运行」。关闭「运行前询问」。如果还能看到「通知时运行」，关掉它，否则每次都会先弹出通知。
6. 添加已导入的快捷指令。如果系统拒绝未签名文件，改用下一节，在这个自动化里手动作。
7. 保存。重启手机后先解锁一次，再发测试短信。

iOS 26 和 iOS 27 的差别主要在自动化的入口和开关名称。26 及以下从自动化标签页的「+」新建「信息」，并直接选「立即运行」。27 及以上更常从导入的快捷指令展开触发器，再打开自动化开关、关闭「运行前确认」。两边都必须有一条匹配规则，也都要在重启后解锁一次。

## 手动添加动作

系统拒绝 `.shortcut` 文件时用这一节。先按上面对应版本建好「信息」自动化，选好立即运行，再添加动作。顺序和下载的模板一致：

1. 如果「信息 › 内容」没有内容：显示通知，标题 `SMSinBox`，正文 `未发送：正文为空`，然后停止快捷指令。
2. 如果「信息 › 发件人」没有内容：文本设为 `（发件人为空）`。否则使用「信息 › 发件人」。把结果设为变量「发件人」。
3. 「文本」：推送链接。
4. 「获取 URL 内容」：
   - URL：上一步的文本
   - 方法：POST
   - 打开「显示标头」
   - 只加 `Content-Type`：`application/json`。不要加 `Authorization`
   - 请求体类型：JSON
   - `from`：变量「发件人」（来自「信息 › 发件人」）
   - `content`：**信息 › 内容**（不要用「快捷指令输入」）
   - `timestamp`：当前日期
   - `device`：文本 `iOS`
5. 看「获取 URL 内容」返回的文字，命中就通知并停止，否则继续：
   - 包含「请求过于频繁」：`未写入：请求过于频繁（429）。请稍后再试。`
   - 包含「推送链接」：`未写入：推送链接无效或已撤销（401）。请在设备页轮换后重贴链接。`
   - 包含 `false`：`未写入：服务器拒绝了这条短信。`
   - 不包含 `ok`：`未发送：网络失败，或返回的不是 JSON。请检查 iPhone 是否联网。`
6. 都不是的话，显示通知，正文 `已转发`。
7. 关闭「运行前询问」，保存。

服务器成功时的 JSON 含有 `"ok":true`，拒绝时含有 `"ok":false`。429 的错误文字是「请求过于频繁」。401 的错误文字是「推送链接无效」或「推送链接已撤销」。判断用这些文字，是为了不依赖 JSON 有没有空格。

## 已有快捷指令和 Android

已经装在手机里的旧快捷指令不用改。它们继续 `POST /api/v1/sms`，请求头仍是 `Authorization: Bearer <设备 token>`。Android 的 SmsForwarder 也继续用这个地址和 Bearer，设备页「Android · SmsForwarder」一节会填出当前站点的 `/api/v1/sms`。

旧的手工动作是：

1. 「文本」：Webhook URL，形如 `https://<你的域名>/api/v1/sms`。
2. 「文本」：设备 token。
3. 「文本」：`Bearer `（Bearer 后面有一个空格），再插入上一步 token 文本的输出。
4. 「获取 URL 内容」：
   - URL：第一个文本
   - 方法：POST
   - `Authorization`：第三个文本（以 Bearer 开头的那个）
   - `Content-Type`：`application/json`
   - 请求体类型：JSON
   - `from`、`content`、`timestamp`、`device` 与上面相同
5. 只要验证码、并且快捷指令自己要停掉无关短信时，在「获取 URL 内容」之前加一个「如果」：快捷指令输入包含「验证码」，否则如果包含 `code`，否则「停止快捷指令」。

设备页只提供统一模板一个下载。收藏夹里的 `?variant=code` 仍会下载旧的关键词模板。新的安装不要用它。

把推送链接当作 Bearer 发到 `/api/v1/sms` 不会成功。认设备只看对应的那把钥匙。

## 常见问题

**导入文件后没有任何反应。** 共享或导入的自动化默认关闭。到「自动化」里打开开关，选择立即运行，并关闭「运行前询问 / 运行前确认」。

**每条短信都要在手机上点确认。** 「运行前询问」或「运行前确认」还开着。iOS 26 及以下选「立即运行」并关掉询问。iOS 27 及以上关掉「运行前确认」，有「锁定时允许运行」就打开。

**重启之后不再转发。** 解锁 iPhone 一次。自动化在重启后的第一次解锁之前不会跑。

**银行或短码短信没有进来。** 正文里往往没有空格，「包含一个空格」匹配不到。把自动化条件改成「包含 验证码」和「包含 code」，或者改成短码正文里一定有的词。不要指望服务端再滤一遍，也不要只靠发件人选择器，它经常只有通讯录。

**iPhone 拒绝打开 `.shortcut`。** 这是未签名备用文件的常见结果。请改用上方 iCloud 分享链接，或按手动步骤在手机上重建。不要为了导入而去掉系统的签名检查。

**收件箱里发件人是「（发件人为空）」。** 「信息 › 发件人」在这一条上是空的，或仍绑成了「快捷指令输入」。编辑 JSON 的 `from`，改用「信息 › 发件人」。服务器接受空的 `from`，占位是为了让你在收件箱里看出问题。

**通知说正文为空，或服务器返回「缺少短信内容」。** 自动化运行了，但 `content` 没有绑到短信正文。把 `content` 改成「信息 › 内容」，不要用「快捷指令输入」。

**通知里是 429。** 这条推送链接一分钟内超过 60 次。等一分钟再试。Bearer 和推送链接分开计数。

**通知里是 401。** 推送链接无效或已撤销。到设备页轮换，新链接只显示一次，贴回快捷指令。撤销会停掉当前链接，但不会换一把新的。

**通知说网络失败，或快捷指令停在系统报错上。** 检查 iPhone 是否开机、是否联网，推送链接是否整段贴上、有没有空格或换行。推送链接为空时，往往还没有 SMSinBox 的通知，系统直接报「获取 URL 内容」失败。

**点了测试按钮，但手机没有收到短信。** 「发送测试消息」是服务器替这台设备写一条测试记录，用来确认收件箱、加密和推送。它不会让运营商发给你的手机，也不会走快捷指令。

**推送链接发到了聊天或工单。** 立刻在设备页点「轮换」。旧链接马上失效，新链接只显示一次。

**填了签名密钥，iOS 还是能上报。** 这是预期行为。推送链接不校验 HMAC。Bearer 那条门仍然要签名。

## 限制

- 必须有匹配规则。空格是最接近「全部短信」的条件，不是真正的全量。
- 手机要开机、联网。快捷指令不在云端常驻。
- 重启后要解锁一次。
- 只有文本，没有彩信，也没有短信里的图片。
- 自动化创建之前的旧短信不会补送。
- 未签名备用模板可能无法导入。优先用本文的 iCloud 分享链接。不要使用来路不明的其它分享链接；分享前清空推送链接文本。
- 一条短信一分钟内、同一设备、同一发件人、正文相同，会被当成重复上报。快捷指令仍会通知「已转发」。
- 推送链接和 Bearer 各有每分钟 60 次的限额，分开计数。
- 真机上的导入、立即运行、空格条件和通知，需要你自己的 iPhone。构建这条仓库的环境不能代替那一步。
